### B · four jugglers

15. **`MAX_JUGGLERS` 3 → 4** (Nico's). `MAX_PARTS` stays 8, which is now exactly 2 × `MAX_JUGGLERS`: a unit test asserts `MAX_PARTS >= 2 * MAX_JUGGLERS`, so five later raises both or fails. Readers, checked: `parsePassing` (five `|` groups give `too-many-jugglers`, `max: 4`; its copy reads `error.max`, no copy change), `isPassingSet` (up to 8 parts), `passingText` (`p<n>` whenever there are not two jugglers), `hash.ts` (`decodeParts` already takes 8 parts; the short link `#3p2-3|…|3p1-3` uses the same grammar). A target digit after `p` stays one character; ten jugglers would need more, which is not this wave.
16. **Lanes stay at four** (governor's call). `MAX_LANES` caps the Rhythm tab's hand-by-hand lanes ("Add a hand" stops at four) and the per-part inputs of the Pattern tab; it is not the stage's cap. A passing set is edited as one passing siteswap (one input, `isPassingSet`), so a four-juggler card's eight hands need no eight-lane editor; the Rhythm tab shows its first four hands, as it shows a three-juggler card's first four today. The juggler and the ladder strip draw all eight (they read `frame.parts`, not `MAX_LANES`). An eight-lane Rhythm tab is a follow-up if Nico wants it; the tunable's comment says what it caps.
17. **Eight lanes in the strip** (governor's call). At the phone's 92 px (sheet open) the eight bands are 7 px, under `LADDER.barPx` (8): bars would cross into the next lane. `laneGeometry` draws a bar `min(barPx, band − rowGapPx)` tall, never under 2 px, one row per lane when the band is that small; a unit test at 8 parts and 92, 112 and 220 px: no bar crosses the next lane's line. Two to six parts draw exactly as today (their tests unchanged). The strip does not grow for four jugglers: it would take the room from the juggler.
18. **Four figures on a phone** (governor's call). Four figures span 3 × `figureStride` + 0.9 = 6.6 units; at a 320 px canvas, width-bound, a figure stride is about 92 px against a caption ("Juggler 4", 12 px) of about 60. The minimum is a 320 px wide canvas: a unit test on the pure layout (`figureSpans` with the scale the canvas uses) asserts neighbouring caption centres at least a caption's width plus 8 px apart at 320, 375 and 390, and the hand bars inside their figure. If the canvas scale is height-bound for a tall pattern the figures only get narrower and further apart in relative terms; the test takes the width-bound worst case. No change to `JUGGLER` is expected; if the test fails, `captionFontPx` is not shrunk, the stride is widened.
19. **Pan for four: the formula holds** (governor's call). `STAGE_PAN` gives centres −0.6, −0.2, 0.2, 0.6 and hands at ±0.2 (`d = min(0.2, 0.6/3)`): −0.8, −0.4, −0.4, 0, 0, 0.4, 0.4, 0.8. Neighbouring jugglers' inner hands meet, by construction (d is at most half the centre spacing); the jugglers stay apart by their drum machines (`DRUMMER_KITS[(j + kitShift) mod 5]` is four distinct kits for j = 0 to 3 at every shift, which a test asserts). The SPEC §6.2 pan row gains the four-juggler line. Three jugglers' pans do not move. (Reversible: a smaller `handMax` would separate four but move three.)
20. **Two four-juggler cards** (governor's call on which; the memory rule on sources holds). Juggling Lab's lists have none (section 1's probe), so each card's shape comes from the Compendium (bibliography 27), its notation from Juggling Lab's conventions as MATH.md §10 and bibliography 26 state them (`p<n>` names juggler n from the left; every juggler starts in the right hand, together), its ball count and cycle from the engine, checked in `presets.test.ts` (juggleable, balls, cycle, predicate 1 by `judge`). This is looser than v6's rule (notation from a source); the PR says so.
    - `four-typewriter`, "Typewriter feed": the Compendium's "Feed with Carriage Return (Typewriter feed)", "D now feeds the clubs from left to right only (C, B, A, C, B, A...)", "A, B and C all pass a 6-count", the feeder on a 2-count. `<3p2 3 3p3 3 3p4 3|3p1 3 3 3 3 3|3 3 3p1 3 3 3|3 3 3 3 3p1 3>`, 12 balls, cycle 6 (worked here: the feeder's right hand passes at pulses 0, 2, 4 to jugglers 2, 3, 4, landing in their left hands at 3, 5, 7; each feedee's pass back at that same pulse lands in the feeder's left hand, which its own right hand never feeds). Short link 59 characters, inside `MAX_PATTERN_CHARS` (64).
    - `four-square`, "Square": the Compendium's "Square (4)": "each person passes with their neighbours on either side", "most triangle patterns can be done in a square". The Triangle card's four-count, one juggler longer: `<3p2 3 3 3|3p3 3 3 3|3p4 3 3 3|3p1 3 3 3>`, 12 balls, cycle 4.
    The builder re-opens the Compendium in the build session and quotes what was read in the bibliography entry 27 (it was opened for the three-feed; add the four-person pages). Names are the source's, in `copy.presets`. Not added: two independent pairs (`<3p2 3|3p1 3|3p4 3|3p3 3>`, two Passing cards side by side, nothing new to hear) and the every-others ring (no source names it, as v6 refused the three-ring). The deck becomes 23 cards; the deck-count test (`e2e/deck.spec.ts`, `presets.test.ts`) and the chip tests (`[2, 3]` → `[2, 3, 4]`) follow.
21. **The JUGGLERS chip "4" is automatic** (checked): `filterChips` counts `cardJugglers` over the deck. Nothing in deck-model.ts changes for it.
22. **The SPEC and MATH.** SPEC §2: a dated v6.6 line, up to four jugglers in passing siteswap and two four-juggler cards.
